# 战役数据深度升级调研（面向近现代战役）

> 缘起：用户反馈「界面没问题，问题是数据——战争沙图做得太粗糙；现代战争做的人挺多」。
> 本文是网上调研的沉淀：业界把现代战争做到什么深度、我们的差距在哪、数据模型怎么升级。
> 结论先行：**差的不是界面，是每场战斗的「日期 / 结果 / 指挥官 / 番号 / 伤亡」五类硬数据，
> 而这些数据对近现代战役全部有公开、可引用的来源**。

---

## 1. 三个业界基准

### 1.1 维基百科战役条目（Template:Infobox military conflict / warbox）

全平台最通行的战役结构化标准，字段即行业标准：

| 字段 | 含义 | 我们现状 |
|---|---|---|
| date | 战役起止日，**战斗精确到日** | ❌ 只有分数年（1948.83） |
| location / coordinates | 地点 + 坐标 | ✅ at/place 已有 |
| result | 标准结果行（「X 胜利 / 不分胜负」） | ❌ 无 |
| combatant1–3 | 交战方 | ✅ sides |
| **commander1–3** | **双方指挥官（≤7 人，阵亡/被俘可标注 KIA/POW）** | ❌ 无 |
| **units1–3** | **部队番号（军/兵团/纵队/师团）** | ❌ 无 |
| strength1–2 | 兵力 | ✅ forces（质量分档） |
| **casualties1–2** | **伤亡：亡/伤/失踪/被俘 + 主要装备损失** | ❌ 无 |
| territory | 领土/态势变化 | 部分（zones） |

数据质量公约（WP:MILMOS#CITE）：一切数字与主观判断**必须给出可靠来源**；宁可留空，不写「未知/？」。
——与我们 war_story_content.js「无把握宁缺毋滥」的引文红线完全同构。

### 1.2 学术冲突事件数据集（UCDP GED / ACLED）

两条主流学术标准（社科院界通行的「事件数据」范式）：每条事件都有
**事件类型、双方行动者、死亡人数、地理位置精度分级、逐条来源引注**。
对我们的教益：战斗不只是一个点，而是「有类型、有主体、有代价、有出处」的事件。

### 1.3 战争沙盘推演视频（B 站，用户的对照物）

「老旦聊历史」辽沈沙盘精讲 104 万+播放、「沙盘上的战争」（上过央视）等——
这类内容的数据语法就是：**双方兵力对比 + 部队番号（纵队/兵团/军）+ 指挥官姓名 +
逐战斗歼敌数 + 阶段推进时间线**。用户觉得我们「粗糙」，粗在没这五样。

## 2. 现代战役数据可得性（调研实摘）

近现代战役的公开结构化数据远比古代丰富，随手可得的样例：

**辽沈战役（维基百科条目，逐战斗伤亡表）**

| 战斗 | 国军损失 | 解放军损失 |
|---|---|---|
| 义县 | 暂20师约1.2万全歼 | 3,000余，炮兵司令朱瑞阵亡 |
| 塔山 | 6千余 | 第4、11纵队各约5–6千 |
| 锦州 | 10万余（死伤1.9万，被俘约8万），范汉杰被俘 | 24,548 |
| 长春 | 10万余（60军曾泽生起义，新7军投诚，郑洞国被俘） | — |
| 辽西（黑山） | 第9兵团5个军12个师约12万，廖耀湘被俘 | — |
| 沈阳 | 13.45万，周福成以下将官106名被俘 | — |

战役级：东野 103 万对国军 55 万；歼敌 47.2 万（毙伤5.68万/俘32.43万），
自损 69,211（**阵亡14,009、负伤53,328、失踪1,874**，出自刘统《中国革命战争纪实·东北卷》）；
编制总表细到「第1纵队李天佑/梁必业、第4纵队吴克华/莫文骅、第10纵队梁兴初/周赤萍」，
国军「4个兵团14个军44个师」分踞沈阳/长春/锦州；三阶段各有日期。

**北伐汀泗桥（1926.8.26–27）**：北伐军约14,000 对北洋军约20,000；北伐军阵亡134、伤256、
失踪5；毙敌千余、俘军官157+士兵2,296、缴炮4门机枪数十挺。指挥官：陈可钰/张发奎/叶挺
对 宋大霈/董政国/陈嘉谟。

**龙潭之役（1927.8）**：孙传芳约6万渡江；国军伤亡约8,000，孙部死伤约3万、被俘约4万、
缴步枪35,000支野炮30门。白崇禧（第2路）/何应钦（第1路）/李宗仁（第3路）对 孙传芳。

**阳夏保卫战（1911.10.18–11.27）**：41–42 天、汉口/汉阳两阶段；黄兴（战时总司令）
对 冯国璋；清军约3万。

**抗日战争**：22 次大型会战有官方逐战统计表（台湾退除役官兵辅导委员会一览表：
含每会战双方伤亡，如豫中会战日军伤亡43,416、国军约20,000）；淞沪 中方70余万/伤亡25–33万
对 日方22–28万/伤亡4万–9万（口径不一，见下）。

### 口径问题 = 数据质量的核心

- 日方《战史丛书》按严格「战殁」口径，自报普遍偏低（淞沪 4 万余）；
- 中方战时数字含宣传成分（台儿庄「歼敌万余」为政治口径；日方档案核心战场战死约2,300，
  按大口径伤亡约1.6万——**时间/地域范围界定不同直接让数字翻倍**）；
- 质量做法：**双方口径并记、各自署名来源**。我们 forces 已有 `quality: recorded/claimed/est`
  + 双语 src 的机制，casualties 直接沿用——这正是本项目相对沙盘视频可以做得更严谨的地方。

## 3. 差距表（现有 battle schema vs 基准）

现有（js/war_data.js，各战 steps[].battles[]）：`side / at / nameZh+En / placeZh+En /
descZh+En / forces[{side,n,quality,src}]`。

| # | 缺口 | 后果 |
|---|---|---|
| 1 | 无精确日期 | 卡片只能显示「1948年 冬十月」级别 |
| 2 | 无 result 标准结果行 | 每场战斗的结局靠读描述自己猜 |
| 3 | 无指挥官 | 林彪/卫立煌/廖耀湘/黄兴/冯国璋/薛岳……全部缺席 |
| 4 | 无番号 | 「第9兵团5个军12个师」「板垣第5师团」级别信息缺失 |
| 5 | 无伤亡 | 沙盘内容的灵魂数据，完全空白 |

## 4. 数据模型 v2 提案（battle 对象扩展）

```js
battles: [{
  side, at, nameZh, nameEn, placeZh, placeEn, descZh, descEn,   // 不变
  forces: [...],                                                  // 不变
  date0: [1948, 10, 14],          // 新：精确起止（战斗精确到日，会战精确到月）
  date1: [1948, 10, 15],
  resultZh: '解放军胜：31小时破城，范汉杰被俘',   // 新：标准结果行
  resultEn: 'PLA victory: walls fell in 31 hours; Fan Hanjie captured',
  commanders: [                    // 新：双方指挥官（≤4人/方，阵亡/被俘/起义标注）
    { side: 'pla', nameZh: '林彪 · 罗荣桓', nameEn: 'Lin Biao · Luo Ronghuan' },
    { side: 'kmt', nameZh: '范汉杰（被俘）', nameEn: 'Fan Hanjie (POW)' },
  ],
  units: [                         // 新：番号
    { side: 'pla', zh: '东北野战军攻锦集团6个纵队+炮纵', en: '6 corps + artillery of the NE Field Army' },
    { side: 'kmt', zh: '第6兵团（93军、新8军）', en: '6th Corps (93rd & New 8th Armies)' },
  ],
  casualties: [                    // 新：伤亡（沿用 quality + 双语出处）
    { side: 'kmt', n: 100000, quality: 'recorded',
      srcZh: '歼敌约10万，其中死伤1.9万、被俘约8万（《中国革命战争纪实·东北卷》）',
      srcEn: '~100,000 lost: 19,000 casualties, ~80,000 captured.' },
    { side: 'pla', n: 24548, quality: 'recorded',
      srcZh: '攻锦部队伤亡24,548（同上）', srcEn: '24,548 PLA casualties taking Jinzhou.' },
  ],
}]
```

**渲染消费点**（UI 增量很小）：
- 气球 `atlas_war.js:1664 _syncWarBalloon`：现有 desc + 兵力行（:1727 war-balloon-forces）
  之后加三行——日期 chip / 结果行 / 指挥官·番号行 / 伤亡行（复用兵力条样式）
- 卡片 `atlas_war.js:1206 _renderWarCard`：当前步骤首个 battle 的同款数据
- 套件：date0 合法且 date0≤date1、casualties 必须双语出处、fate 词表校验、
  与既有「无出处宁缺毋滥」红线一致（可空字段允许缺省）

**引文红线同构**： casualties 与 quote 同一政策——只录有出处的数字；双方口径并记时
用两条 casualty 记录（各署来源），不取「平均值」。

## 5. 实施路线

1. **试点：近现代 4 场（42 步）全量加深** —— 每个战斗补 date/result/commanders/units/
   casualties；来源：维基条目逐战伤亡表 + 官方党史网（12371.cn）/国防部战例复盘 +
   《中国革命战争纪实》/日本《战史丛书》（口径并记）。现代战役数据全公开可得，
   42 步 × 平均 2-3 个战斗是本轮工作量主体。
2. **渲染端**：气球 + 卡片加行（一次通用改造，所有战役受益；空字段自动隐藏）。
3. **古代 21 场（另议）**：史书有记载的补（如《史记》级「斩首 X 万」可作 recorded；
   淮南「风声鹤唳」类只留 desc）——按引文红线宁缺毋滥，逐场处理。
